发布记录

P4 · 登记与核验。人声明的和人核验过的，永远是两组字段。
「已发布」是两件事，不是一个勾。 你点「已发布」时，系统并不真的知道平台那边发生了什么。
declared（你声称的）= 链接 / 作品 ID / 发布时间；verified（人核验过的）= 状态 / 时间 / 核验人。 声明永远不覆盖核验结果，核验失败也不抹掉你声明的链接。
登记人必须是真人。 接口层把 registered_by / verified_by 固定为 user， 不读客户端传的值 —— 模型不能替你把东西标记成已发布。 核验人传 system / model / ai 会被直接拒绝（VERIFIER_MUST_BE_HUMAN）。

核验结果的含义

verified_state含义与后续动作
confirmed 链接可打开、内容与发布包一致。可以开始按窗口采集数据。
mismatch 这是一个有效结论，不是「还没核验」。平台上的内容与本地发布包不一致 —— 先查清是哪一版被发出去的，不要急着导入数据，否则数据会挂到错的稿子上。
inaccessible 链接打不开（已删、仅自己可见、区域限制）。同理，这是结论， 不代表内容没问题，也不代表能拿它当基线。
null 未核验。页面必须显示成「未核验」，不得显示成「正常」或任何正面措辞。
