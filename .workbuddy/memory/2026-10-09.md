# 2026-10-09

## 1. 放开"只允许本机访问"（v1.4.1 → v1.4.2）
用户反馈：局域网/其它设备访问时前端显示「创作设置未读取：账号连接只允许本机访问」，工作台基本没法用，要求"删除全部这种相关限制"。

根因：`backend/app/api/accounts.py` 的 `local_request` 是**一个依赖挂 5 个 router**（`accounts` / `studio` / `content_skills` / `douyin_publishing` / `videos`），旧规则要求"客户端回环 + Host 是本机名"，非本机全 403 → 连 `/studio/options` 都读不到，前端只会显示上面那句话。看着像账号功能坏了，其实是整个应用。

改法（保留真正有意义的边界）：
- 非回环客户端**默认放行** —— 新增 `Settings.allow_remote_access`（`CWB_ALLOW_REMOTE_ACCESS`，默认 `true`）。能收到非本机请求本身就说明服务已被绑到可访问地址，再按客户端 IP 拦只是把内网访问打死。
- **Host 校验保留**（防 DNS rebinding）：本机名 ∪ `CWB_ALLOWED_HOSTS` ∪ 私有/回环/链路本地 **IP 字面量**。只放行 IP 字面量是刻意的——rebinding 必须借攻击者自己的域名。
- 同源（`Origin`）、拒 `Sec-Fetch-Site: cross-site`、写操作要 `X-CWB-Local-Action` 头，三条恒开。
- 想恢复旧行为：`CWB_ALLOW_REMOTE_ACCESS=false`。

## 5. v1.4.3：启动脚本默认绑局域网（用户选择"默认绑局域网，开箱可用"）
`scripts/launcher.py` 原本在两处写死 `--host 127.0.0.1`（`start()` 与 `restart_api()`），docstring 里说的"局域网能用"其实还要用户自己翻命令行。改动：

- `DEFAULT_HOST = os.environ.get("CWB_HOST", "0.0.0.0")`；新增 `--host` 参数（`start.bat --host 127.0.0.1` 即可恢复只本机）。
- **API 命令只有一个来源**：`api_command(port, host)`，`start()` 与 `restart_api()` 共用；`restart_api` 从 `services.json` 读回 host，不会偷偷退回只绑本机。
- 启动时用 `announce(open_urls(...))` 打印回环地址 + 内网地址，`lan_addresses()` 跳过 TUN/WSL 段（本机实测识别出 `10.6.101.1`）。
- `ensure_query_service` **保持绑回环**（`test_query_startup.py` 明确断言 query 只绑回环，这个不放松）。
- 顺手修掉自己写出来的一个坑：`lan_addresses()` 一开始会抛异常，而它在 `start()` 的 health 轮询 `try` 里被 `except Exception: pass` 吞掉 → 启动永远"未就绪"、重试 30 秒后报错。现在发现地址是 best-effort，异常一律吞掉并返回空列表。

回归断言加在 `backend/tests/test_query_startup.py`（10 → 18 通过）：默认 host、命令单一来源、回环时只播回环、虚拟网段判定、`--host` 传到 `start`、`start` 真的用该 host 起 API 并写进 `services.json`、`restart-api` 复现记录的 host。

版本号四处同改到 v1.4.3，缓存 token `20261009-lan1` → `20261009-lan2`（52 处；顺手把 `QueryLab.html` 里遗漏的 `app.js?v=20261007-query` 也归一成新 token，那个文件一直用旧 token 引用 app.js）。README 与 `docs/QUICK_START.md` 写清局域网打开方式与"无鉴权"的安全提醒。
