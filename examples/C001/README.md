## 已确认与暂定

- 已确认：抖音＋小红书；先跑通一轮真实内容生产，再决定开发工具；尽可能自动化，人工承担监督，减少审核频次；用户手动上传发布的安排仍保留。
- 首轮形式调整：图文优先。抖音与小红书共用一份有证据的内容母稿，分别制作封面、分页和文案；不把视频、配音或 Seedance 接入设为首轮依赖。个人运营、AI 工具实测与工作效率仍为暂定定位。
- 第一轮目标：从一个确认选题产出两个平台的发布包，发布后取得一次可核查复盘，并产生下一批选题。第一轮不以涨粉或爆款作验收门槛。
- 试验范围：先完成一题两份内容；流程可行后再累计约 6 个选题。数量是执行建议，不代表统计显著性。

## 一轮闭环与分工

| 步骤 | AI 的工作与交付物 | 人需要做什么 | 进入下一步的条件 |
|---|---|---|---|
| 账号定位 | 草拟受众、内容承诺、表达风格、内容边界 | 首次确认服务谁、自己擅长什么、希望获得什么 | 定位有明确版本；后续仅变化时再确认 |
| 调研 | 查资料、保存来源、交叉核对、形成证据卡 | 平常无需介入；仅补充系统拿不到且必要的材料 | 关键事实有依据；缺证据时先换角度或删掉该主张 |
| 候选选题 | 按定位、证据充分度、可制作性、重复度排序，自动选择并起草 | 可随时否决或改方向；新赛道/新立场才集中确认 | 处于已定定位范围；记录自动选择理由，不冒记人工确认 |
| 实测与素材 | 在已有权限内执行可复现实验、取证；制作可溯源的图文和回放素材 | 仅在必要的线下实测、本人经历或访问障碍时介入 | AI 执行写成 AI 实测；本人未体验不写本人亲测 |
| 脚本与平台改写 | 母稿、双平台改写、标题封面、引用核对；自动修订 | 不审核中间稿 | 事实与证据匹配，不支持的主张先删除或降级表达 |
| 素材制作与质检 | 首轮交付双平台图文成品与发布文字；检查事实、错字、分页、截断、对比度与证据 | 一次集中预览双平台成品和异常摘要 | 自动检查通过，再送最终预览；失败不得伪装通过 |
| 发布 | 生成可直接上传的文件和文字；整理一次发布包 | 在上传时完成最终确认并手动发布 | 明确发布确认或有效发布记录；不把未回复当同意 |
| 数据回收 | 对可访问的数据自动整理、校验、计算；接入方式需实测 | 接入前仅提供一次后台导出/截图；只确认无法自动消除的歧义 | 有采集时间和口径；缺失标注，不阻塞其他可分析部分 |
| 复盘 | 自动分析、生成下一轮选题并在既定范围内应用小幅调整 | 看周期摘要；仅方向或定位改变需决定 | 原始证据可查，变化有版本和回退点 |

日常固定检查点压缩为一次：发布前集中预览，合并到手动上传环节。选题、脚本、封面、字幕和复盘不再逐项请求批准。首次定位和必要异常另计；可选本人配音/拍摄不算默认流程。

## 自动推进与异常处理

正常路径：调研 → 自动选题 → 脚本与改写 → 素材制作 → 自动质检与修复 → 一次成品预览/手动发布 → 数据整理 → 自动复盘 → 下一批选题。

- 每个阶段交付给下个阶段，不等待用户回复“继续”。前提是能力可用、任务处于已定方向和权限范围内。
- 事实检查使用来源比对；数据使用确定性计算；成品检查可读性、字幕与画面对应。自评“高置信度”不能替代这些检查，也不能保证零错误。
- 可自动修复的问题先修，最多两轮；之后先尝试不依赖该项的可交付版本。仍影响成品时才放入异常清单，说明失败点、建议方案和需要用户决定的最小事项。
- 必要异常包括：核心事实无法核实；必须由本人提供的经历或线下证据；登录/验证或授权障碍；超出已定费用范围的服务；改变账号定位或对外立场。能移除的非必要主张不为此打断用户。
- 异常按一条内容或一批集中提交，避免逐条弹问；不阻塞其他独立内容。涉及必须确认的操作仍等待明确决定，超时不会自动批准。
- 发布预览只呈现双平台成品、推荐标题、尚未解决的事项与重大改动；来源和过程记录默认折叠，按需展开。审阅决定采用“通过 / 一句话修改 / 暂缓”。
- 后续常规排版修复自动执行；修改已批准成品的事实、观点或核心画面时，将新版本加入同一预览队列。所有正式发布仍由用户手动完成。

减少用户劳动也要影响选题选择：优先使用已有材料、可由 AI 执行的实验、可程序化排版的内容。必须外拍、采访或本人长期体验的题材不作为默认首选；必要时单独标出投入。

## 第一轮实际交付

1. 确认一张选题卡，建立内容编号 C001。
2. AI 优先整理现有真实记录、制作可溯源画面并检查制作工具；只有无法替代的素材才向用户索取。保留失败、修改与人工介入。
3. 抖音目标交付：建议 4–6 页图文成品，开头直接呈现问题或结果，正文每页一个观点，附推荐标题/封面/描述。具体发布规格以实际账号界面核对；页数是编辑选择，不是平台限制。
4. 小红书目标交付：5–7 页图文成品、推荐标题/正文；备选标题只做折叠备查，不强迫用户逐个选择。页数是试验选择，不是平台规则。
5. 用户一次集中预览成品，手动发布两条。系统尽量从发布链接补齐记录，无法获取的字段才请用户提供。
6. 建议发布后约 24 小时、72 小时、7 天各留一个数据快照，记录实际采集时间。这是本实验的观察安排，不是平台通用最佳窗口；尚未创建自动提醒。
7. 用真实数据做一次复盘，自动提出并排序下一轮选题；既定范围内直接进入准备，用户可在最终预览时否决。

## 如何判断有用

首轮必须能回答：人在哪些步骤介入；哪些 AI 产出被直接采用；哪些需要重写；有没有错误事实；人实际花了多少时间；两个平台能否顺利发布；数据是否可回到原内容。额外记录人工打断次数、审核分钟数、主动操作分钟数、自动修复次数和必须人工解决的异常数。

设计目标：常规每条内容只触发一次发布前集中检查，双平台预览与决定争取控制在 3–5 分钟；手动上传、首次配置和例外任务另外计时。这是待验证目标，不能当作已经达到的成绩。若超出，先排查反复确认、成品质量和素材依赖，不把额外工作默认转给用户。

分别记录 AI 等待时长、人工操作分钟数、总历时、修改轮数与实际费用。没有同类手工作业基线时，只报告本轮耗时，不声称节省百分比。可另外选择一个规模相近任务做手工对照，但不因此阻塞首轮。

传播效果单独观察：两平台按图文后台实际提供的曝光、浏览、互动、收藏与关注数据分别记录，不强套视频完播率。若提供翻页等指标，保留原始定义；不假定所有账号都能导出同一组字段。看板中不存在的字段记为缺失，不补零。

## 形式选择：先图文，后视频

本项目优先验证选题、信息价值和低人工负担。采用结构化文案、固定但有变化的版式、可核查记录/示意图，生成插画只在有信息价值时使用。中文正文通过排版层绘制，方便修改和自动检查，不要求图像模型一次画对整页文字。图文容易生产不等于自动获得传播效果，仍需真实发布验证。

视频分两种后续路线：其一为已验证图文加旁白、字幕与少量动效，可复用素材；其二为 Seedance 等生成动态镜头，需要单独验证参考素材、镜头控制、重试率、审片和总成本。两者不能混为同一个成本级别。

截至 2026-10-01 查阅，[Seedance 2.5 官方说明](https://seed.bytedance.com/en/blog/one-take-creation-flexible-referencing-introducing-seedance-2-5)介绍了多模态参考、单次最长 30 秒及时间戳编辑能力；这些能力说明不能证明本项目无需人工即可稳定出片。没有进行模型对照实测，也没有核实适用于用户账户的完整价格，不断言便宜模型必然更差。

模型选择后续按“每条可发布成品的总成本”衡量：所有生成与重试费用、配音/剪辑费用、审核修改时间一并计入。先固定内容标准、最多重试次数和预算，再比较可用成片率。AI 工具实测中的界面操作与结果必须来自实际记录，生成视频仅能作标明用途的示意画面。

## 数据复盘的约束

- 两平台分别分析，使用相同发布后时长比较同平台内容。曝光、阅读、播放不可合并当同一指标。
- 原始平台指标名称和分母必须保存。自行计算的收藏率等必须标注分母；缺失或为 0 时不计算。
- 总账号涨粉不能当作某条内容的带来关注数。投流与自然流量、不同内容形式、重大外部热点要单独标记。
- 第一条内容只建立基线。相关性和个别评论不能证明因果，也不能证明平台“限流”。
- 评论归类为问题、质疑、经验补充、需求、无效内容，附匿名原文摘录及样本数。保留异议；不自动回复或删除评论。只保留分析所需的最少个人信息。
- 每次复盘分别列“观察事实、可能解释、下一步验证”。尽量每轮只改变一个主要变量，如开头表达；其余变化也需记录，不能把自然发布当严格随机 A/B 实验。

## 跑通后怎样做成工具

第一版只需要五个工作区：账号档案、选题与证据、制作与审阅、手动发布记录、数据与复盘。每项内容有唯一 ID；母稿与平台版本分开保存，数据快照只能附加，规则变更保留理由和版本。

状态：候选 → 已选定（记录 AI/人工及理由）→ 素材齐备 → 自动制作 → 自动质检 → 待集中预览 → 可发布 → 已发布 → 待数据 → 已复盘。异常另入处理队列，正常任务继续；驳回回到对应制作步骤。没有有效发布记录或人的发布确认，不能自动标为已发布。

后续 AI 模块按输入输出拆分为 research、topic、draft、adapt、review。工作流保存任务状态、产物版本、人工决定、失败原因与重试；skills 只负责具体方法。后台数据先支持手动输入/文件导入，再评估授权 API。用户手动发布保持为既定流程。

开发顺序：一题两平台人工协同试跑 → 累积几题确认字段稳定 → 做本地轻量工作台 → 按重复劳动最多的环节逐项接入自动化。当前交付是试跑方案和操作模板，不是已接通 AI/API 的应用。
