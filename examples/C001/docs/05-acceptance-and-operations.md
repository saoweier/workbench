# 验收、测试与运行设计

设计 v1.1。这里定义执行方应提供的证据，不代表测试已执行。工程验收与外部集成验收分开：缺少 API、实际账号或后台样本时继续可独立的开发，真实业务验证标 pending。详见 06。

## 1. 分层验收

| 层 | 必须看到的证据 | 不能替代的东西 |
|---|---|---|
| v0 图文交付 | C001 实际图片、一次预览、ZIP、真实上传核对 | Markdown 文案或占位图片 |
| 自动生产 | 新输入产生新成品、真实 Provider request_id、来源及运行记录 | fixture 固定返回 |
| 可靠运行 | 故障注入、重启恢复、预算阻止、批准版本校验 | 只有正常路径录屏 |
| 反馈闭环 | 真实发布记录、真实数据快照、可回溯复盘 | 自造点赞、阅读或评论 |
| 低人工负担 | 实际打断次数、预览时间、修改次数 | 宣称“90% 自动化”但没有分母 |

## 2. 必测场景

| ID | 场景 | 通过条件 |
|---|---|---|
| A01 | C001 双平台导出 | 正文、页序、封面与实际文件匹配；manifest 哈希正确；用户可手动上传 |
| A02 | 自动流程无异常 | 从批次启动到预览中途不要求人确认；两个平台都可查看 |
| A03 | 引用不存在/关键事实无证据 | 被检查阻止；自动补证据、删主张或进入集中异常，不能直接批准 |
| A04 | 文本过长、中文字体缺失、图片失效 | 检出并有限修复；无空白图或截断文字被标为通过 |
| A05 | 只修改某一页 | 创建新 revision；相关页面/检查重跑，不重复生成无关内容 |
| A06 | 用户看旧预览时后台有新稿 | approve 返回版本冲突；旧批准不对应新图 |
| A07 | 批次重复提交/HTTP 重试 | 相同幂等键返回同一任务；不同参数同 key 返回冲突 |
| A08 | Worker 在生成后、登记前被终止 | 重启根据检查点/产物恢复，不漏产物，不产生两个已生效 revision |
| A09 | 租约过期后旧 Worker 返回 | fencing token 阻止旧结果覆盖；旧结果仅作审计/对账 |
| A10 | Provider 超时但可能已收费 | 标记结果未知，保留预留并先查询；不可无上限重复调用 |
| A11 | 可选硬预算耗尽、实际费用超估算 | 仅 hard_cap 模式执行金额阻止；实际超差如实记录，不把账单截为预算值 |
| A12 | 取消时远端请求仍运行 | 不派发后续阶段；晚到响应可记费用，但不恢复 canceled 流程 |
| A13 | 单平台失败 | 另一平台保持可审状态；总体显示部分完成，不伪称双平台完成 |
| A14 | 未批准导出/下载后状态 | 草稿明确标记；正式发布包须批准；下载不等于 published |
| A15 | 重复导入同一文件 | 不重复添加数据/评论；重新映射或修订保留来源链 |
| A16 | 缺失、0、时间区间、不同平台分母 | 明确区分；分母缺失或为 0 不计算；不同口径不直接比较 |
| A17 | 无作品匹配、截图数值歧义 | 进入必要匹配/核对项，不自动猜测绑定或补值 |
| A18 | 复盘没有足够数据 | 输出局限及流程观察；不杜撰效果，不归因限流 |
| A19 | 网页/评论包含执行命令 | 仅当作内容，不执行工具、读密钥、改预算或批准 |
| A20 | 超出本地目录的路径或内网 URL | 输入被拒收，重定向同样校验，不读取非授权路径 |
| A21 | 备份恢复 | 用独立测试目录恢复数据库与产物，历史版本可读、哈希有效、任务可正确继续 |
| A22 | 自动下一轮达到库存/额度上限 | 保存候选而不继续付费制作；不会无限生成 |
| A23 | 未配置 API 或搜索 | 本地 seed 渲染/导出仍可运行；真实调用明确提示缺配置；资料模式不冒称联网搜索 |
| A24 | usage_tracking，金额上限为空、价格未知 | 已配置启用 API 后，用户启动的有限任务可执行；用量正常记账，金额 unknown，不强迫填预算 |
| A25 | Provider 只有 tokens，无金额或 usage 缺失 | 保存存在的原始字段；无单价不换算；估算、供应商回传、账单对账分别展示，缺失不填 0 |
| A26 | API 配置保存与测试 | 保存不触发外部调用，密钥只在服务端；测试按钮发有限请求并记录结果/用量 |

## 3. 测试实施范围

- 单元：状态转换、预算预留/结算、指标分母、字段映射、版本哈希与审批条件。重点验证业务不变量，不写逐行复刻实现的测试。
- 集成：SQLite 事务/租约、文件登记、真实渲染、Provider 假服务模拟超时与重复响应。供应商适配器另做少量有预算的真实契约测试。
- 端到端：主要覆盖生成到预览、改稿到重新批准、发布登记到导入复盘三个用户路径；用真实渲染图片，fixture/真实运行状态明显区分。
- 人工：代表性页面在正常桌面和窄屏预览、内容事实抽查、实际上传核对；不要求用户每个内部步骤都参与验收。

常规提交运行受影响测试；涉及核心状态/版本/成本时跑相关集成；发布前运行关键端到端与恢复试验。真实模型调用与耗费不在每次普通测试中默认触发。

## 4. 试运营记录与指标

建议连续记录 6 个内容包作为工程试跑。首次两个包用于校准界面、模板与规则；后续观察人工负担，不把该数量视作统计显著性样本。

每包记录：是否真实调用、模型/提示词版本、来源、初稿和终稿、图片、Provider 用量及已知/未知费用、错误与修复、人工打断次数、审核时间、修改原因、发布链接、数据快照。

指标定义：

- 常规审核轮次：用户对同一内容包作出的成品检查次数，修改后的再审也计入。
- 人工打断次数：系统要求用户提供信息/做决定的交互次数；同一异常的重复催问额外计数。
- 人工审核分钟：实际检查成品的有效时间，不把后台等待算在里面；页面打开时长仅作代理值，允许用户修正。
- 人工操作分钟：上传、导出后台数据、补素材等另记，与审核时间分开。
- 自动修复率：系统自行解决的可修复问题数 / 检出的可修复问题数；未检测到的问题不能计为成功。
- 合格成品成本：该内容所有尝试、失败、重试、渲染与可选图片费用总计；不同币种分别展示，缺失费用标未知。
- 周转历时：批次启动到成品就绪，另拆等待人工/外部接口的时长。

目标：常规一次集中检查；双平台预览争取 3–5 分钟；无已知关键事实错误、无已知截断图片交付。目标未达到就记录偏差与改进，不修改分母使结果好看。传播表现单独观察，不作为软件能否正确运行的替代指标。

## 5. 日常运行

开始一批：读取固定 profile_version → 检查 Provider 与库存/次数限制，若启用 hard_cap 再检查金额 → 启动 Worker → 在站内展示进度。默认一批一题；增加批量需修改设置，不靠模型自己扩大。金额未设不阻塞 usage_tracking。

通知：成品就绪、必要异常、最终失败、预算耗尽。按内容包聚合，同一未变化异常不反复提醒。

暂停：停止领取新任务，在途任务尽可能完成当前安全检查点；界面明确哪些调用仍可能计费。取消后不再自动恢复。关机/休眠会停止实际执行，重启再续跑。

## 6. 备份与恢复

本地启动工具提供 backup/restore；使用 SQLite backup API 或经验证的一致快照方法，不能只复制正在写入的 app.db 而忽略 WAL。产物先不可变写入再登记，备份记录数据库快照对应的 artifact manifest。

备份包含数据库、所引用文件、模板/提示词/配置版本及校验清单，不含密钥。首版手动一键备份，升级前必须备份；定时备份作为后续可选设置，不在本轮创建系统定时任务。

恢复到新目录并校验：迁移版本兼容、所有引用文件存在、哈希匹配、任务状态可回收。通过后再切换数据目录。孤立文件隔离后清理，不自动删除用户原始资料。

## 7. 最终交付清单

- 可启动的独立仓库与锁定依赖；Windows 启动/停止和故障说明。
- 数据迁移、模板、提示词及来源 registry。
- 至少一个真实内容包及其一次集中预览/手动发布证据。
- 真实数据回收与复盘例子；如缺失，明确完整闭环尚未验收。
- 关键测试报告、恢复演练、费用与人工负担实测记录。
- 已知限制及后续计划，明确平台连接和生成视频哪些尚未接入。
