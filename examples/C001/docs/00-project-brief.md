# 项目定义与文档导航

版本：设计 v1.1 · 2026-10-01。项目暂名：内容工作台。本文记录设计，不代表执行方已实现应用。所有验收指标均为目标。最新执行要求见 06：用户不需先交制作包，API 使用时配置，费用追踪为默认、预算上限可选。

## 1. 产品目标

面向一个人运营抖音、小红书的场景，把研究、选题、写稿、图文制作、检查和复盘连成可恢复的自动流程。人首次设定方向，平时集中看成品、处理必要异常，手动发布。

优先验证两件事：内容是否具体有用；人工参与是否少到值得长期使用。首先交付图片与发布文字，再逐步自动化。现有 C001 文案是第一份真实种子素材，不是已经做好的成品。

## 3. 产品范围

### v0：能做出图文

输入现有文案和素材 → 结构化分页 → 模板排版 → 导出图片 → 一次预览 → 下载发布包。以 C001 完成双平台交付，用户手动发布并提供首次反馈。

### v1：图文生产闭环

增加真实搜索接入、证据保存、自动选题和文案、自动检查/局部修复、可恢复任务、预算记录、人工发布登记、数据文件与评论导入、复盘产生下一批选题。常规流程不逐步要求确认。

### 后续版本

可靠的后台数据连接器、经批准的定时批次、更多版式、图文转简单视频。Seedance 等生成式视频在独立实验验证质量和成本后再纳入。

### 首版不做

自动发布、自动评论/私信、登录托管、绕过平台访问限制、全网大规模抓取、多人权限系统、云端 SaaS、视频生成、复杂向量库、第三方 skill 市场。人工上传保留为发布边界，不因“尽量自动”默认为授权对外发布。

## 4. 默认使用方式

1. 首次填写账号方向、受众、表达偏好、不能编造的经历、参考来源与单批条数。模型/搜索在 API 设置页按使用需要配置；默认追踪实际消耗，金额上限可不填。赛道暂用 AI 工具实测，可修改。
2. 点击“生成本批内容”，系统在范围内自动选题、制作、检查。默认一批一个选题，两个平台版本；通过试跑再增加批量。
3. 成品集中出现在一个待发布队列，用户看图片和正文，点击“通过”“一句话修改”或“暂缓”。
4. 用户下载并手动发布；粘贴链接或登记平台作品 ID。下载成功不等于发布成功。
5. 真实运行有数据后，用户提供后台导出与评论文件，系统分析并准备候选；已启动批次范围内可继续制作。没样本时先用标准模板开发，不能阻塞其他模块。

下一轮自动准备不是无限循环：有批次数量、待审库存、调用次数/重试限制与暂停开关；金额上限可选，未设置时按 API 实际消耗追踪。关机期间不保证执行；尚未创建任何定时任务。

## 5. 产品验收目标

- 常规一条内容只有一次集中预览，合并两个平台；修改导致的再次预览如实计数。
- 单条双平台预览目标 3–5 分钟，首次配置、上传时间与异常另记；不以省略检查达成目标。
- 交付真正可上传的图片、正文和来源记录，而非仅给脚本或要求用户自己排版。
- 可中断、恢复、回退；失败只重做受影响阶段，不重复生成整个批次。
- 关键事实有来源，无法核实的主张自动移除或进入异常；AI 自评分不能代替事实验证。
- 不混淆演示数据与真实后台数据，不跨平台混用指标分母。

具体测试见 05；业务目标为“低人工负担下稳定交付”，不承诺涨粉或爆款。

## 6. 已定决策与待验证条件

| 项目 | 当前决定 | 验证时机 |
|---|---|---|
| 平台与形态 | 抖音、小红书，图文优先 | v0 用实际发布界面验证规格 |
| 人工参与 | 一次集中预览＋手动发布；必要异常集中处理 | 每轮统计 |
| 应用位置 | 独立内容项目，沿用本地 Windows 环境 | 建仓时确定目标目录；不并入报价系统 |
| 数据存储 | 首版单机 SQLite＋本地文件 | P1 恢复试验 |
| 模型与搜索 | 设置页配置 API，不写死厂商；先完成一种文本协议及搜索适配边界 | P0 定契约，P2 实现；用户配置后补真实验证，不必先预估金额 |
| 图片生成 | 可选增强；首版可只用文字排版与真实截图 | P1 即可无生图服务交付 |
| 后台数据 | 首版标准导入模板，fixture 明确标识，真实映射之后补 | P4 工程可先实现，真实样本不作为开工条件 |
| 本地运行 | API、任务执行进程持续运行时自动推进；非云端常驻 | P1 验证退出与重启行为 |

缺少账号密钥不阻塞本地图文渲染开发；缺少真实数据不允许声称复盘闭环已完成。
