设计修订 v1.1 · 2026-10-01。依据用户最新明确要求：暂时没有制作包；模型希望走 API 配置；费用以实际 API 消耗为准，现阶段无法预估金额。本文与同步修改的 00–05 文档作为新的执行基线。

## 可直接交给执行模型的任务说明

请继续开发，不要把 C001 成品、平台登录、确定提供商、预算数字和后台样本一起作为开工条件。

1. C001 是首个内容编号，成品应由系统/开发方产出。使用现有 C001-production-pack.md、topics.md 和 seeds/C001/seed.json 整理首个样稿，不要求用户另交制作包。现有资料不支持的事实删除或标注待验证，不编造实测成果。
2. 平台规则先做可配置 profile，使用明确标为“待平台实测”的工程默认尺寸和页数。开发排版、预览、导出无需先登录平台；真实上传兼容性留作独立集成验收。
3. 做 API 设置页，支持接口类型、Base URL、API Key、模型 ID、超时、输出上限和连接测试。文字与搜索分别配置。提供商与模型不写死，不要求用户先在聊天里报密钥或选定厂商。没有配置时显示未配置，可继续使用本地 seed 和明确标识的 fixture 开发。
4. 成本默认实际用量追踪，金额上限可选。用户不填人民币预算不能阻塞开发，也不能在其已配置并启用 API、主动启动有限任务后仅因单价未知而阻塞调用。按供应商实际账单核对；只拿到 tokens 时显示用量，金额未知不填 0。费率换算结果标为估算，不能冒充实际扣费。
5. 没有后台样本，先做标准模板、字段映射、导入校验和测试样本。测试数据明确标为 fixture，不混入正式复盘；拿到实际样本再补平台原生映射和真实效果验收。
6. 立即推进 P0 工程契约与 P1：本地应用骨架 → 结构化稿件 → 真实 PNG → 集中预览 → ZIP。真实付费调用、平台发布和数据反馈的业务验证逐项登记为待集成，不阻塞其他模块开发。

## 2. API 设置设计

### 文字模型配置

字段：name、adapter_type、base_url、secret_ref、model_id、timeout_seconds、max_output_tokens、enabled、capabilities、last_test_status。可选费率单独存，不作为连接必填项。

前端支持新增、编辑、启用、测试连接、选择默认配置。密钥输入后由服务端保管，只返回是否已设置及掩码，不回显全值。保存配置不自动发起真实调用；“测试连接”和“开始生成”使用该配置发起有限调用，并在动作旁说明可能产生实际消耗。

配置不等于万能兼容。第一版完成一种明确的文本协议适配器；其余端点如协议不同，需要新增 adapter，不靠更换 Base URL 假装已经适配。模型支持 JSON Schema、图片输入或用量回传等能力分别检测，失败给出可理解的错误。未回传用量不伪造 tokens。

### 搜索配置

独立适配器和密钥，返回 URL、标题、摘要与来源信息。普通文字模型不默认具有联网能力。首版没有搜索配置时允许导入链接/粘贴资料继续生成，界面标明“基于提供资料，未执行自动搜索”；自动调研的真实验收留待接通搜索。

### 状态

unconfigured：缺必要配置；configured_untested：已保存未测；available：最近测试成功；error：具体失败。真实任务故障可更新状态，不能永久依赖一次成功。Fixture 和 local_seed 是运行模式，不是 Provider 可用状态。

用户配置的模型端点与研究网页 URL 分开校验。端点可以显式允许用户自己的本机服务，研究网页读取仍拦截内网目标；不得因为支持本机模型就放开任意网页访问内网。

## 3. 实际消耗优先的成本模型

默认 cost_mode=usage_tracking，batch_money_limit=null、daily_money_limit=null；null 表示未设置金额限制，0 表示零额度，不能混同。

逐次保存：Provider、模型、请求编号、原始 usage、输入/输出/缓存用量（存在才记）、成功/失败/结果未知、开始结束时间、重试关联、币种、计费状态。计费状态至少包括 unknown、estimated、provider_reported、reconciled。

展示原则：

- usage 是实际接口回传的用量；可能没有金额。
- 有费率表时按其版本估算，分别处理计费类别；不支持的计费方式保持未知。
- Provider 回传金额时标注来源；账单对账后的金额才标为已对账。更正追加审计记录。
- 按任务、内容包、批次及日期汇总；不同币种不直接相加；部分费用未知时显示“已知金额＋N 笔待核实”，不能显示为完整总价。
- 可后续设置金额提醒或硬上限。只有启用硬上限时才要求足够的计价/预留依据；无法估价时暂停该模式的付费任务并说明原因，不影响默认追踪模式。

未设置金额上限不意味着无限调用：每批默认 1 个内容，待预览库存上限 3，内容修复最多 2 轮；网络重试有限、单调用有超时和输出上限。Provider 请求结果未知先查状态，不能无脑重发。任务有阶段数/总调用数限制和暂停取消；循环研究不能无上限生成。

自动准备下一轮在当前用户启动的批次范围内执行；超出范围只保存候选。以后启用定时批次需单独配置执行频率与数量。没有 API 配置时不消费；本次修订没有发起真实调用或配置密钥。

## 4. 工程验收与业务验收分开

每阶段维护 development_status 与 integration_status，而不是只有一枚“完成”勾选。

- P0 工程完成：seed/契约、默认规格及配置设计就绪。无需账号、密钥、金额数字或真实导出。
- P1 工程完成：seed 到双平台 PNG、预览、批准版本、ZIP 可运行且通过验证。上传界面未核对时标 integration_pending。
- P2/P3 可用 fixture 和故障模拟开发及验证状态逻辑；真实 Provider 端到端运行仍为单独验收项。
- P4 可完成标准导入和复盘算法；实际平台映射和真实复盘分别等待样本，不能把假数据成果称为真实效果。
- 可以交付本地开发预览版，明确尚缺的集成证据；完整业务闭环验收仍需要真实发布和回收数据。

未满足真实业务条件时保留待验证标记，继续可独立完成的工程工作。不要反复让用户一次性补齐全部条件。
