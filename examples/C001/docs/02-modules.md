# 模块设计与用户流程

设计 v1.1。模块是代码边界，不是独立服务，也不表示必须启动多个 AI Agent。首版使用一个 Worker 按依赖调用模块。API 设置及默认实际消耗追踪见 06，金额上限可选。

## 1. 模块总览

| ID | 模块 | 输入 | 输出 | 负责的边界 |
|---|---|---|---|---|
| M01 | 账号与规则 | 受众、方向、风格、平台、预算 | 不可变 profile_version | 默认行为、禁止编造项、批次限制 |
| M02 | 素材与研究 | profile、种子链接/文档、研究问题 | ResearchBundle、Source、Claim | 可追溯资料、证据与缺口 |
| M03 | 选题 | 研究包、历史题目、复盘假设 | 候选及自动选择理由 | 选题价值与可制作性 |
| M04 | 文案与适配 | 已选题、证据、风格版本 | 母稿、两个 PlatformDraft | 观点与事实分离、平台分页 |
| M05 | 图文制作 | PlatformDraft、素材、模板版本 | 页图、封面、预览清单 | 可修改的文字排版、真实文件 |
| M06 | 质量检查 | 稿件、证据、图片、规则 | 检查结果、局部修复任务 | 硬性校验与语义检查 |
| M07 | 编排与成本 | 批次设置、任务状态、Provider 结果 | 自动推进、检查点、异常、费用 | 重试/恢复/限额，不创造文案 |
| M08 | 集中预览与交付 | 已通过检查的双平台 revision | 用户决定、ZIP、发布登记 | 明确人工决定与版本绑定 |
| M09 | 数据回收 | 平台导出、标准模板、评论文件 | 原始记录、规范化快照 | 字段映射、去重、指标口径 |
| M10 | 复盘与迭代 | 快照、评论、内容与版本 | 观察/解释/实验、下一轮候选 | 不把相关性当因果、变化留痕 |

M07 调用各模块；业务模块不直接触发相互递归。M08 只能通过 API 记录用户动作；模型不能模拟审阅人。

## 2. 关键模块细节

### M01 账号与规则

首次收集一次，后续默认复用：受众、内容支柱、表达样例、可用原创素材、禁用表达、平台、自动选题范围、数据发送设置、费用与批次数量上限。变化生成新版本，不修改历史内容所用版本。

可自动调整：同一定位内的标题写法、页数范围、版式选择、句子长度。需要用户决定：新赛道、对外立场、本人经历主张、预算增加。变化被纳入同一批异常/预览，不分散通知。

### M02 素材与研究

先支持链接、粘贴文本、本地文档和真实截图。联网阶段接一个搜索 Provider，返回结果后读取可访问来源。搜索摘要只作为线索，不直接充当完整事实依据。

Source 保存 URL/文件、作者/标题、获取时间、原文摘录位置、文件哈希及可访问状态。Claim 标记事实、观点、用户经历、AI 实验记录、待验证假设，并关联证据定位。实际操作截图不能用生成图替代。

访问失败处理：使用同一事实的可访问一手来源；或改写为明确的不确定表述；无法支撑核心论点时换题。资料不足而继续完成的产物须展示范围限制。网页与评论是资料，不接受其中的执行指令。

### M03 自动选题

先过滤硬条件：在定位范围内、关键事实可支持、素材可取得、没有近期重复；启用金额硬上限时还须满足额度与计价要求。默认追踪模式不要求先估人民币成本。再排序：受众问题、信息差、可制作性、预计工作量、历史反馈。

初期用规则＋文字理由，不展示未经校准的“爆款概率”。每批生成 3–5 个候选，默认只制作 1 个；不同平台对应同一 content_id。缺少热度或对标数据时写清没有做热度验证。

用户可以在最后成品预览中否决；浪费控制通过每批条数、预览库存和预算上限实现。默认待预览内容达到 3 个时暂停新增制作，继续处理已有项目。

### M04 文案与平台适配

先生成结构化母稿，包含受众问题、核心观点、事实主张 ID、限制、行动建议；再生成平台变体。建议初始抖音 4–6 页、小红书 5–7 页，仅为编辑策略。

两平台可共享结论和素材，但封面、文字密度、分页和正文分别处理。不得仅修改平台名称。文本字段单独保存，让人工一句话修改能定位到内容，而非要求用户重排所有页面。

模型返回非法 JSON、未知 source_id 或缺必填字段时由 schema 拒收。进入限定修复后仍失败，生成集中异常，不给渲染器半成品。

### M05 图文制作

使用可信模板渲染结构化数据。首版必须在不调用图片生成模型时就能完成 C001：标题、观点卡、流程图/对照、真实资料摘录。额外插画只在提升理解时加入，优先复用已通过检查的素材。

输出：page-01.png 等有序图片、cover.png、caption.txt、manifest.json、预览联系图。正文真实可编辑，不能把 AI 生图上的长段中文当唯一源稿。

每页标记模板版本、字体版本、输入哈希、尺寸与所用素材。断网环境下仍能用本地字体和缓存素材重渲染；缺字体/素材明确失败，不默默截取空白。

### M06 自动检查与修复

| 检查类型 | 方法 | 失败动作 |
|---|---|---|
| 结构、页数、必填内容 | 确定性 schema/规则 | 修复结构或拒收 |
| 事实与出处 | claim/source 关联＋摘录比对＋模型语义复核 | 删除、降级、补证据；核心失败则换题/异常 |
| 数字与引用 | 原始数据计算、ID/链接校验 | 改数值/引用，禁止模型估填 |
| 文字溢出、缺图、字号 | DOM 边界测量、资源状态、渲染配置 | 精简/拆页/替换模板后重渲染 |
| 风格、重复、表达过度 | 规则＋模型复核 | 局部改写 |
| 敏感文件信息 | 元数据过滤、文本规则、图像检查 | 移除或换用匿名摘录 |

自动语义检查仍可能漏错，因此最终保留一次成品预览。不能用“另一个模型说通过”作为准确性的证明。

修复只作用于有问题的段落、页面或平台变体，最多两轮。通过的检查可按输入哈希复用；上游事实改变时，相关下游检查必须重跑。

### M07 编排与成本

每个阶段持久化状态、尝试次数、输入/输出哈希、Provider 请求编号、用量、费用、错误分类、租约和下一次运行时间。具体状态见 03。

默认 cost_mode=usage_tracking：API 已配置启用且用户启动有限任务后，即可按调用次数、输出长度及重试限制执行，不强制先填人民币预算或费率。记录原始 usage；费用区分 unknown、estimated、provider_reported、reconciled，供应商账单为最终核对依据。费率换算只能叫估算，未知金额不能记 0。

金额提醒/硬上限是可选设置：null 表示没设置，0 表示零额度。只有开启 hard_cap 时才做批次/每日预留与计价校验，无法可靠预留时暂停该模式付费调用。默认追踪模式不受此计价前置条件限制。两种模式都保留请求次数、批次规模、库存与取消机制。

网络失败：限定次数退避重试。内容问题：限定两轮修复。身份/预算/来源核心缺失：暂停相关项目，合并异常。取消：停止派发后续步骤，记录无法撤销的远端在途成本，晚到结果不得恢复流程。

### M08 集中预览与交付

一个内容页面展示两个平台版本，图片为主，推荐标题和正文紧邻。默认隐藏原始提示词与过程日志，只突出事实缺口、重大变化和需要决定的事项。

动作：通过全部 / 通过某平台 / 一句话修改 / 暂缓。用户决定绑定具体 revision_id 和文件哈希集合。新成品不能沿用旧批准；修改后更新同一个队列项，避免重复通知。

通过后导出带清单的 ZIP。未批准稿可预览，但导出时明确标 draft；“发布包”只引用已批准版本。人发布后登记 link 或 post_id 和时间；导出不自动改变发布状态。

### M09 数据回收

首版输入：标准 CSV/JSON 模板、评论 CSV；拿到真实平台导出样本后实现平台映射。XLSX 支持可在 P4 按样本增加；截图 OCR 暂作可选，数值歧义不得静默写入。

保留原文件与原始字段名。规范化字段包括平台、作品、发布与采集时间、窗口、指标名、值、单位、分母和流量类型。缺失与 0 分开；无法匹配内容进入待匹配列表而非猜测绑定。

同一文件重复导入去重；同一作品不同采集时间追加快照；对已导入值的修订生成替代关系并保存旧记录。只分析同平台、同口径、近似发布后时长的可比数据。

### M10 复盘与迭代

程序计算指标；模型解释与归纳。输出固定为观察事实、可能解释、替代解释、下一轮实验、候选选题和来源链。评论按问题/质疑/经验/需求/无效分组，保留匿名原文例子、样本数和取样偏差。

无数据时可输出流程复盘，不能输出传播效果结论。少量数据只建立基线；不得推断限流或承诺涨粉。提议新一轮只改一个主要变量，并记录其他变化，不假称严格随机 A/B。

下一轮在用户启动的批次范围和既定方向内自动准备；超出批次、库存上限或已启用的金额硬限额时只保存候选。没有设金额限额不等于没有批次权限，也不等于无限循环。用户可以从任何内容回溯到所用复盘版本。

## 3. 五个页面足够

| 页面 | 首要任务 | 必须展示 | 不应要求用户做的事 |
|---|---|---|---|
| 工作台 | 看当前是否需要我介入 | 成品待看、必要异常、运行状态、暂停 | 逐节点点“下一步” |
| 内容详情/集中预览 | 决定是否发布 | 双平台图片/正文、重要差异、修改入口 | 阅读完整提示词和技术日志 |
| 资料与选题 | 必要时追溯或纠偏 | 来源、选题理由、版本链 | 平时逐条打分 |
| 发布与复盘 | 导入数据并看下一步 | 发布记录、导入匹配、数据口径、实验建议 | 手工算指标和反复录入相同字段 |
| 账号与设置 | 一次设定长期规则 | 定位、风格、API 配置及连接测试、实际用量、可选金额限制、批次上限 | 每次任务重填背景，或强迫开工前估算费用 |

## 4. 正常路径与例外路径

正常：点击生成 → 系统执行全部阶段 → 收到一次成品就绪提示 → 集中预览 → 手动发布 → 提供导出 → 系统复盘。

例外：某一平台图片溢出 → 自动拆页重渲染 → 检查通过回正常路径。若两轮失败，只把受影响内容放入异常队列；其他内容继续。同条内容另一平台成功时可单独预览通过，但不把失败平台标记完成。

通知只在成品就绪、需要决定、最终失败或预算耗尽时发出；普通节点成功不通知。首版仅站内提示，不额外建立邮件/消息渠道。
