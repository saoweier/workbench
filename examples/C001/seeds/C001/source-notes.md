# C001 开发输入说明

此目录解决 T01 的启动输入问题。用户不需要先做出图文成品；开发方直接读取 seed.json，即可开发和验证分页、排版、预览、审核版本与 ZIP 导出。

## 文件性质

- seed.json 是根据现有项目文案整理的真实项目草稿，共抖音 5 页、小红书 6 页。
- 它不是用户提供的媒体素材包，不是已发布作品，也不是应用调用 API 自动生成的记录。
- local_seed 表示读取固定草稿；fixture 用于另外构造的假接口/假后台数据。两者均不能伪装为真实模型运行或实际后台效果。
- 没有嵌入图片、密钥、账号信息、API 消耗或虚构阅读点赞量。

## 开发方执行

1. 校验 JSON、连续页序、claim_ids/source_ids 引用。
2. 为两个平台创建独立 draft revision，保存输入哈希；不得生成批准或发布记录。
3. 以工程默认 1080×1440 PNG 渲染 cover/checklist；此尺寸可调整，verified=false，并非平台规则。
4. 使用本地字体与程序化排版，不依赖生图 API、搜索、录屏或本人配音。
5. 检查文字溢出、缺字、页序、图片尺寸及文件可读性；生成预览。
6. 在本地应用里验证一次集中审阅与 ZIP 导出。未实际上传平台时保留待上传核对状态。

## 来源与证据范围

相对路径以本目录为基准，seed.json 的 sources 指向项目 README、制作稿、选题确认记录。开发方应把文档和 seed 一起拷入独立工程的 examples/C001 等目录，或调整路径并重新校验。

主张刻意限定为：项目选择了什么、现有文案准备到哪里、接下来希望验证什么。任何“提高效率多少”“涨了多少粉”“模型自动完成了全部生产”等结论均未获证据，不得加入。

若执行方只有 seed 而未收到其他文件，可以完成本地渲染验证；来源完整性标为 missing_local_source，不要求用户重新制作资料。上线内容应删去无法核实的事实，或取得对应文档后核查。文件存在仅能证明文档内容存在，不能证明设计已经实现。

## T01 完成状态

策划侧已补齐输入 JSON 与来源说明。执行方仍须完成导入、schema 校验及渲染连通验证后，将 T01 的工程部分登记完成。不能因为本目录存在就将真实发布或自动生成验收标为通过。
