## 生产方式改变

1. 文字模型现在逐页生成视觉计划：图解类型、具体对象、说明文字和本页结论。真实图文稿须包含至少三种图解、一个具体填写示例和一个流程或关系图。
2. 图解说明提供解释、判断条件与具体操作；发布正文包含问题、方法、示例、边界和行动，避免仅输出几个关键词。
3. 程序负责实际绘图与排版：六种版式分别绘制，封面包含创作桌面矢量插画。所有图解文字来自稿件结构，图片内文字可准确排版。
4. 长内容自动切换紧凑排版并在安全区域内适配；过度缩小或越界会被拒收，避免截图成功但成品文字重叠。
5. 标题按自然语义断行。图片可以在预览页放大、翻页阅读，旧稿可通过“制作图文新版本”升级。后台进度支持刷新后继续查看。
6. 视觉内容与模板版本进入版本指纹。更换图解也会产生新版本，旧稿与旧批准保留。

当前配图是本地绘制的插画和信息图，不是摄影图片，也不声称调用过生图模型。文字模型 API 足以驱动这套图解生产，不需要额外图像 API；尚未提供按主题生成写实照片的能力。

## 真实调用及修复

使用用户已配置的 `deepseek-flash`。本轮只处理 C009 已生成的公开文档方法内容和编辑建议，没有发送内部项目文件。新增四次真实文字模型调用，其中包括三次抖音生成/格式修复尝试与一次小红书生成；HTTP 调用成功不等于稿件一次通过验收。

实际模型会把固定格式标记 `type=json_object` 带入稿件。只对这一确切的非业务标记作兼容，其他未知字段及批准、状态、文件路径等越权字段继续拒收，原始供应商响应不改写。恢复时复用了已经返回的抖音稿，没有重复发送。

真实长稿暴露了关系图、流程和清单挤压的问题，已修复自适应布局。渲染恢复复用组成稿检查点；最终 v3 仅复用已完成的文字稿，零新增模型调用。新版资料限制更正了“原文摘录”的标注：输入实际是公开文档摘要，不是逐字引用。

最终复跑还定位并修复了模拟稿的偶发平台差异不足：一百组不同请求中旧模拟数据有十七组不符合原差异标准，修正后的全部一百组通过。正式生产与旧稿升级均保留差异检查，复制稿只改平台名仍会被拒收。

所有十二次累计真实调用（本轮四次、前轮八次）均可在 C009 溯源中查看。没有配置单价，因此费用保持未知，不能当作零费用。
