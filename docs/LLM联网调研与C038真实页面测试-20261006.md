# LLM 联网调研修复与真实页面测试

## 实际故障

C036（`0faafa4c-5dcf-4e54-8523-68618d594f5e`）的调研失败发生在公开搜索入口：百度返回302，跳向验证码页面。旧实现只有这一入口，既没有备用入口，也没有让文字模型拆分检索目标。上一轮模拟测试覆盖了“没有正文就停止”，没有证明真实搜索能取得正文。

第一轮改造后，C037进一步暴露：文字模型将“AI预测”误解为必须查到一个公开发表的AI预测模型，并使用过长的英文检索词；搜索工具将不相关的插件和AI教育页面作为成功结果。事实核验挡住了错误内容，但检索方向仍错。这条失败记录保留。

## 已修复

- 模型通过冻结的调研 Skill 规划检索词，工作台执行搜索与读取网页工具，再由模型核验返回正文。文字接口本身没有浏览器，联网由工作台工具完成。
- 优先保留用户语言、核心题目和明确时间范围；制作措辞不作为检索目标。“让AI预测”不等于要求调研已发表的AI预测系统。
- 搜狗、必应、百度提供备用搜索入口。遇到重定向/验证页时不跟随验证、不解决验证码；切换另一入口。无相关标题的结果不能算作成功搜索。
- 未配置独立搜索接口时使用公开网页工具；配置后同样使用模型检索计划，优先已配置搜索接口。
- 搜索结果只是线索，必须读取正文。保留失败链接、来源哈希和原文摘录，不把摘要升级为事实。
- 语义核验指出核心缺口后可针对缺口补查；结果未知的模型调用不吞掉、不自动重发。
- 规则在“资料调研与核验” Skill 维护：`单轮检索词数量：3`、`补充检索轮数：1`。这些是工具调用预算，不是内容条目上限。
- 诊断页展示模型检索计划、搜索入口和网页读取结果。预览的搜索状态读取实际任务记录，不再用是否存在收费搜索API调用来猜测。
- 失败任务侧栏不再仍显示“后台正在处理”。教程补充联网工具和诊断说明。
