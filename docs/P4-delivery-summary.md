## 五条你会直接感受到的设计

### 1. 「已发布」不是一个勾，是两组字段

你点「已发布」时，系统并不真的知道平台那边发生了什么。

所以：**你声称的**（链接、作品 ID、时间）和**人核验过的**（状态、时间、核验人）
是两组独立的字段，谁也不覆盖谁。

而且「未核验」在页面上显示的就是**未核验**，不会显示成「正常」——
没核验过和核验过没问题，是两种完全不同的状态。核验结果为「不一致」或「打不开」
是**有效结论**，不是「还没核验」。

### 2. 缺失 ≠ 0

解析不出数字时存 `None`，不写 0。

这条看起来技术，实际很要命：「这次没采到播放量」和「这次播放量确实是 0」
在复盘里指向完全相反的动作。写成 0 会把「平台没回传」伪装成「内容彻底没人看」。

### 3. 评论分类可能出错，所以每组都带原文

分类用的是**可读的关键词规则**，不是模型推断。每一条都附上原文和判断理由，
你可以直接核对、直接纠正。页面上会一直挂着一句：
「分类是系统的判断，可能出错；请用原文例证核对。」

比例数字的**分母永远是本次导入的样本量**，不是全部评论数 ——
只给百分比不给样本量是耍流氓。

### 4. 复盘先说数据够不够，再说看到了什么

分四级：无发布 / 有发布无数据 / 单点数据 / 多窗口可比。

**「没有数据」和「数据不好」是两件事**，前者推不出后者。
数据不够时报告会明说「没有效果可复盘」「无数据不等于表现差」，
而不是硬挤出一个结论。

观察只是陈述（「播放量 12000」），**不带因果**（不会说「因为封面好」）。
想解释就必须走假设那条路，而**假设必须给出替代解释** ——
只写「封面更好所以播放高」会被拒：

> 给不出竞争解释，说明手里是直觉而不是假设。

### 5. 下一轮建议默认不生效，而且都能撤回

系统只把复盘结论**起草成候选**，然后停下等你筛。

- 只有幅度 **tiny / small** 允许系统自动采用
- **medium / large** 即使请求自动采用也**降级为仅候选**
- 没有证据引用的建议**直接拒绝**：「否则它就不是从数据来的，只是凭空的想法」
- 每条采用过的都存了原值，**随时可回退**

页面上没有任何「自动执行」按钮。接口明确声明 `auto_apply: false`。

## 这一阶段发现并修掉的 5 个问题

| # | 问题 | 为什么值得记 |
|---|---|---|
| 1 | 一行数据写一条快照 | 平台导出是长表（同一时刻多个指标占多行），一行一条会把「一次采集」拆散，还直接撞唯一约束 |
| 2 | 自然/付费流量被合并 | 流量类型原来藏在数据内部，去重逻辑看不见它 → **「这波投流带来多少」永远算不出来** |
| 3 | **试算把正式导入写坏了** | 一个标着「只预览」的动作往幂等表写了记录，撞上约束报错，而且**连累紧随其后的正式导入也失败** |
| 4 | 复盘时付费流量被藏起来 | 每份发布只取一个数据快照，自然和付费互相顶替，投流效果无法归因 |
| 5 | 建议列表永不清空 | 采用/拒绝/回退后的条目还赖在待办里 → 列表越用越长 → 人开始整片忽略它 → **等于没有待办列表** |

第 3 条最典型：它是被测试逮住的 —— 试算之后再正式导入会**立刻失败**。
如果没测试，这会等到你第一次真实导入时才炸。

## 为什么还不能算「能用」

工程完成 ≠ 业务可用。这一步差的是**真实数据**，不是代码。

| 缺什么 | 影响 |
|---|---|
| 真实 Provider Key | 内容生产链路的真实质量未验证（你已说明 P3 后配） |
| 平台上传规格核对 | `platform_upload_verified = false`，尺寸目前是工程排版值 |
| **一份真实的平台导出文件** | 我全部用的是手造 CSV。真实导出的列名、时区写法、单位习惯（「万」还是「w」）、同一时刻会不会重复导出 —— 都还没见过 |
| 6 个内容包的真实试跑 | 只能证明「程序没有越界」，不能证明「复盘结论有价值」 |

所以 P4 的集成状态如实登记为 `integration_pending`。
**不把 fixture 通过当作真实链路可用的证据。**
