# 直接创作与 HotPush 热点

## 使用方法

1. 打开“内容生产”，直接输入题目；或者点“热榜选题”，从实际热点中选择。
2. 选精简、均衡或详细，选择表达风格和篇幅，点“开始制作”。参考资料和配图放在选填区域。
3. 在预览查看实际页图，点“更短更精简 / 更详细 / 更活跃 / 更精致”，或写自己的修改要求，再生成新版本。
4. 新版保留旧版，可以对照。每版都需要人工批准，批准后才导出或准备发布。

原题、明确 TOP 数量、页数、统计时间范围会成为结构约束。例如“TOP10，1～2页”不会变成三类教程或五页说明。文字里的页数优先于篇幅下拉框。信息密度和风格不修改主题、对象或排序口径。资料不足时说明需要补什么，不换题。

排行榜专用版式支持 TOP1～TOP12、1～8页，名次跨页连续。超出支持范围时明确报错，不擅自减少对象或截掉页面。TOP10 可以一页列完整榜单，也可以封面加榜单，共两页。排行榜模型只输出条目、名称、理由与文案，程序确定版式和连续名次，不让模型自行选择封面/图解类型。规划一页允许列出完整TOP10及口径，避免通用“四个要点”限制挡住排行榜。

## 热点来源

仅从 [JackyST0/hotpush](https://github.com/JackyST0/hotpush) 的公开 `/api/hot/stream` 接口取得全部来源。默认服务地址是该项目 README 提供的公开站点；“HotPush 服务设置”可换成自己的兼容服务根地址。工作台不直接抓取原平台，不要求登录热点平台，不调用 HotPush 推送接口。

当前上游内置13源：微博、知乎、B站、V2EX、Hacker News、掘金、IT之家、NodeSeek、少数派、豆瓣热映、豆瓣新书、联合早报、澎湃新闻。新增的自定义来源只要由聚合接口返回，也会接入。

“全部热点”保留每源全部有效条目。生活、科技、游戏是本地题材筛选，视频、影视、阅读、新闻按来源分类。编号表示上游返回顺序，资讯流不因此成为全网热度榜；没有热度值时显示未提供。热点标题和描述属于待核验的参考信息，不能凭热榜标题证明文章观点。

榜单陆续进入页面，不等待最慢来源。读取不调用文字模型，页面不会自动创作。正常缓存15分钟；手动刷新可提前更新。失败时保留旧快照并标明时间与状态；没有成功数据的来源显示暂不可用。

2026-10-05 16:34（北京时间）实际读取：全部13个来源可见，成功12源，共261条；Hacker News本次没有返回有效数据，页面明确显示暂不可用。10月4日首轮成功10源、228条是历史记录。实际来源数量和条目数随上游更新变化。

“上个月GitHub热门Skill TOP10”需要该自然月的真实统计资料。HotPush当天热点、当前累计星标、滚动30天趋势均不能自动代替该自然月数据。可以在选填区提供原始榜单或统计快照；材料不足时工作台会要求补充。

## 实现与边界

- 原三角度推荐界面移除，旧推荐接口返回410；新接口为 `/studio/produce`、`/studio/contents/{id}/revise`。
- 结构化简报来自用户原文，外观说明不会参与题型判定；否定要求不选择被禁止的题型。
- 规划、母稿、平台稿使用同一页数约束；非法规划拒收，不截断模型页内容冒充成功。
- 名次数量、对象重复、跨页编号受确定性校验；语义审核检查是否回答原题与符合资料口径。
- 参考资料保留输入范围内的完整原文，避免只取前400字而丢掉榜单后半部分。
- 当前版本提供七个流程技能和七个题材技能，保留版本、输入与执行结果，在“内容团队”可修改规则和查看记录。新增模板选择与具体约束见[题材技能与内容模板](CONTENT_RECIPES_20261005.md)。
- 文字模型、图片模型分别配置；提供图片或显式调用图片接口后才使用实际配图。模型审核不能替代人工图片检查和批准。
