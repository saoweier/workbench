# C018 事实错误诊断与修复

## 已证明的错误链

原题：这菜吃了能不烧心吗是什么梗。用户要求：做一个活泼一点的梗指南。

原 V1 没执行资料搜索。唯一来源 U01 是系统编辑提纲，不能证明梗的来源或含义。规划阶段首次产生“饭桌、美食视频、红油重口味调侃”的无来源解释；生成按这个解释续写；审核虽然看到资料不足，仍返回 passed=true。文字模型接入成功不等于模型有联网资料。

这是调研证据边界、规划和审核的共同缺陷，不只是某条文案写得不好。历史输入输出和原始模型返回保留；历史版本未存完整请求，页面明确注明，不能重建冒充原始请求。

## 本次修复

- 题目、编辑提纲、热点快照、搜索摘要、仅有链接不当作事实依据。
- 热点继续只用 HotPush；资料调研是独立阶段，尝试读取用户来源链接、已配置搜索结果正文，必要时使用内置公开网页搜索。
- 核心资料缺失或搜索遇到验证时停止，并显示失败原因，不靠模型记忆补写。
- 热梗调研必须输出原始语境、实际含义、来源编号和原文引用。逐字验证允许空白排版变化，保存时还原为来源中的实际片段，不允许改字、错配来源。
- 原始语境和最早首发分开处理。未考证最早首发不等于不能归因介绍已读资料；AI生成来源必须披露，不称独立核验。
- 独立规划入口、生产入口、审核入口都加入证据检查；旧错误稿也不能因历史“待预览”状态跳过批准检查。
- 热梗使用独立内容框架，不再套入饮食选购指南。显式两页约束贯穿规划和两平台产物。
- 新任务保存模型请求内容、实际返回、规则快照和分步记录；诊断递归遮盖密钥字段。

## 实际验证结果

真实模型 deepseek-flash 已完成 V2。抖音、小红书各两页，均已渲染为1080×1440图片，当前为待人工预览，未批准、未发布。V1保留。

这次重做使用三条公开原文链接；并非自动公开搜索成功。两篇新浪来源注明AI生成，潮新闻为另一篇评论资料。V2作来源归因，明确最早发布与传播统计未核验。文章观点不自动等同于独立证实。

真实验证脚本只读，不增加模型请求。验证23项包括来源、含义、页数、披露、图片哈希、实际页面诊断和无脚本异常。该内容累计记录14次模型请求，本次新增7次，包括被拦截的调研尝试；恢复阶段复用已保存结果，不重复发送已完成请求。

测试证据在 `docs/test-artifacts/meme-diagnosis-20261005/`。程序证据检查、来源读取、技能版本及诊断页面的专项回归在 `backend/tests/test_evidence_grounding.py`。
