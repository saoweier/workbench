# 引导式创作：推荐选题到图文预览

日期：2026-10-04。根据用户反馈，将工程表单改为系统引导、用户补充的创作流程。

## 怎么用

1. **找灵感**：六类常青题材提供具体方向，也可以只输入一句想法。配置文字模型后默认使用当前模型，打开页面不会自动调用模型。
2. **定角度**：推荐三个选题，分别说明受众、切入角度、推荐理由和页提纲。可以补充“多给示例”“不用付费工具”等要求再推荐，也可以直接带着补充要求继续。
3. **确认生成**：选题与提纲自动带入，选择抖音/小红书及表达风格，补充要求或资料后确认。系统自动创建一条受许可约束的生产批次并排队，显示阶段进度，完成后打开真实图片预览。

手动表单和离线工具移入高级折叠区。草稿和任务入口保存在当前浏览器，重新打开后可继续；其他浏览器或清除浏览器存储后不会带入该草稿。已提交的后台任务仍保存在业务数据库。

## 推荐依据与热点范围

- 六类题材库是编辑建议，没有实时排名。
- 科技热点使用 [Hacker News 官方公开接口](https://github.com/HackerNews/API)，按用户点击获取当前讨论，展示原题目、来源、发布时间、社区赞与讨论数以及获取时间。原题目保留原文，选中后可由文字模型推荐中文切入角度。
- 热点不是抖音或小红书平台热榜，未读取外部文章全文。元数据不能替代事实证据；没有原始资料时，只做方法建议或明确标注的虚构示例。
- 缓存有效期十五分钟；失败时标注旧缓存，完全没有结果时明确说明。程序只请求固定公开 API，不读取用户输入的任意 URL。
- AI 推荐属于编辑提案，界面明确说明事实与平台热度尚未核验。

本次在当前运行服务上实际取得六条公开社区讨论，来源与原时间正常显示，见 [实际热点界面](test-artifacts/creation-trends-live-20261004.jpg)。

## 生产行为

用户确认的题目在生产中固定，使用原有选题硬条件与待预览许可检查；后台不会再次选择另一个题目。人工确认记录使用独立事件。

用户受众、角度、提纲和补充要求单独进入母稿与双平台改写提示词，并保存在队列请求和创作事件中。它们不作为事实来源。没有提供资料时，明确使用编辑提纲支持方法草案，避免误用 C001 项目文件。

提交具有持久幂等标识，重复点击返回同一个任务；同标识不同内容拒收。生成继续使用原有后台任务、检查点、恢复、图文排版、人工批准及发布后回填流程。用户仍需在预览页确认成品。

推荐文字调用也进入用量日志与请求日志；重复的相同推荐复用完成结果，未知结果阻止重发。输出有额度限制，不完整 JSON 会明确失败并保留原草稿。
